# Flower OMS — дорожная карта

Номера в скобках ссылаются на таблицу проблем в [PRODUCT_REVIEW.md](./PRODUCT_REVIEW.md#4-проблемы-ux-логики-и-данных).

**Как устроена работа по каждой задаче:**

- отдельная ветка и отдельный PR;
- проверки `npm run typecheck`, `npm run lint`, `npm run build`;
- проверка сценария в браузере на ширине 1280 и 390 px;
- скриншоты «до» и «после» в описании PR.

**Когда нужно согласие владельца:** если задача меняет схему БД, логику денег или данные клиентов. Такие задачи отмечены значком ⚠️.

---

Без изменений схемы БД. Только исправление ошибок и UX.

## Волна 2 — важные функции

| # | Задача | Критерий «готово» |
|---|---|---|
| 2.1 | **Статус «Отменён»** (5) ⚠️. Нужны причина, возврат цветов на склад и исключение из выручки. Что делать с внесёнными деньгами (возврат или депозит), решает владелец. | Отменённый заказ не входит в «Toplam məbləğ» и «Borc», цветы вернулись на склад (есть `StockEvent`), в истории указаны причина и автор. |
| 2.2 | **Долг как состояние** (3) ⚠️. Поле срока возврата, фильтр «Borclar», отчёт по должникам, баланс в карточке клиента. | На `/orders?debt=1` видны все заказы с долгом. У клиента показан общий долг. После погашения заказ пропадает из списка. |
| 2.3 | **Получатель, текст открытки, анонимность** (7) ⚠️. Нужна миграция. | Поля есть в форме, в карточке, у флориста и в CSV. Старые заказы работают. |
| 2.4 | **Печать открытки и накладной для курьера** (формат A6 и 80 мм). | Кнопка «Çap et» формирует страницу печати с текстом открытки, адресом, получателем и суммой к оплате курьеру. |
| 2.5 | **Правильные переходы статусов** (11). Откат назад только для админа и с комментарием. | Проверено на всех ролях: запрещённый переход возвращает 403 и понятный текст. |
| 2.6 | **Касса и отчёт по дате оплаты** (12). Вкладки «Kassa» и «Sifarişlər», итоги по сотрудникам и способам. | Сумма по кассе за день совпадает с суммой всех `Payment` за этот день. |
| 2.7 | **Гибкие способы оплаты** (17) ⚠️. Справочник: наличные, карта, перевод, онлайн, курьеру. | Админ добавляет способ. Он появляется в панели оплаты и в отчётах. Старые оплаты отображаются верно. |
| 2.8 | **Склад: приход, списание, себестоимость** (16) ⚠️. | Приход с ценой и поставщиком, списание с причиной, отчёт «Движение склада». Маржа заказа = сумма − себестоимость цветов. |
| 2.9 | **Доставка** (18) ⚠️. Стоимость по зоне, окно времени, роль «Kuryer» с мобильным экраном, фото вручения. | Курьер видит только свои доставки, отмечает «Çatdırıldı» с фото и принятой суммой. Отчёт по курьерам. |
| 2.10 | **Карточка заказа как сводка** (14, 23). Фото разделены на образцы и готовый букет. | Все ключевые данные видны на первом экране 390 px. Редактирование по кнопке. |
| 2.11 | **Каталог букетов** (шаблон, фото, цена, состав). | Выбор шаблона в новом заказе заполняет сумму и образец. Флористу показывается состав. |
| 2.12 | **Уведомления клиенту через WhatsApp** (click-to-chat шаблоны, позже API). | Из карточки заказа одной кнопкой открывается WhatsApp с готовым текстом («заказ готов» или «доставлен») и фото. |
| 2.13 | **Напоминания о датах клиентов** (день рождения и свои поводы). | На панели оператора список «Ближайшие 7 дней» с кнопкой «Позвонить или написать». |

## Волна 3 — рост и SaaS

| # | Задача | Критерий «готово» |
|---|---|---|
| 3.1 | **Мультиарендность** ⚠️: модель `Shop`, `shopId` везде, изоляция данных. | Автотест: пользователь магазина A не видит и не меняет данные магазина B ни через один API. |
| 3.2 | **Филиалы**: склад и заказы по точкам, сводные отчёты. | Заказ привязан к филиалу, отчёт можно фильтровать по филиалу. |
| 3.3 | **Регистрация и онбординг** (мастер + демо-данные). | Новый магазин за 10 минут без помощи доходит до первого заказа. |
| 3.4 | **Подписка и биллинг** ⚠️ (тарифы, пробный период, местный эквайринг). | Оплата продлевает доступ. Просрочка переводит магазин в режим «только чтение» без потери данных. |
| 3.5 | **Онлайн-витрина и форма заказа** (ссылка для Instagram и WhatsApp). | Заказ с витрины появляется в `/orders` со статусом NEW и каналом «Sayt». Опционально онлайн-оплата. |
| 3.6 | **Канал заказа и аналитика** (звонок, WhatsApp, Instagram, сайт, зал). | Отчёт по каналам: число заказов, выручка, средний чек. |
| 3.7 | **Отслеживание заказа клиентом** (QR и ссылка). | Клиент по ссылке видит статус и фото готового букета без входа в систему. |
| 3.8 | **PWA и push-уведомления** для флориста и курьера. | Приложение ставится на главный экран. Новый заказ приходит push-уведомлением. |
| 3.9 | **Бэкапы, мониторинг, журнал аудита, политика конфиденциальности.** | Ежедневный бэкап базы и фото, восстановление проверено. Алерт при недоступности. |
| 3.10 | **Публичный API и вебхуки** (1С, бухгалтерия, маркетплейсы). | Документированный REST API с ключами для каждого магазина. |
